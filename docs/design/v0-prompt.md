# v0 프롬프트 — UI 디자인 일괄 적용 (#111)

v0(v0.app)에 넘길 프롬프트와 사용 절차. 디자인 언어가 화면마다 어긋나지 않도록
**4개 화면을 한 채팅에서 한 번에 생성**하고, 코드 이식은 Step a→d로 나눈다.

## 절차

1. v0 새 채팅에서 아래 "초기 프롬프트"를 그대로 붙인다.
2. 결과를 보고 "후속 프롬프트"로 톤·레이아웃을 다듬는다. 이 단계에서 확정할 것은
   색·타이포·간격·컴포넌트 모양이며, 기능은 건드리지 않는다.
3. 확정된 결과에서 Step별로 코드를 가져온다.
   - **Step a**: shadcn/ui 초기화(ADR 016), `globals.css`의 `@theme` 토큰, Pretendard 폰트,
     헤더·푸터 컴포넌트, 루트 레이아웃
   - Step b: 홈, 목록(카드·필터바·페이지네이션·빈 상태·스켈레톤)
   - Step c: 상세(헤더·필드 표·첨부·본문·원본 링크·404)
   - Step d: 구독(로그인 유도·계정 표시·채널 토글·Sprint 3 필터 자리)
4. 이식할 때 기존 컴포넌트의 구조와 시맨틱은 유지하고 `className`과 마크업 껍데기만
   바꾼다. 기존 E2E 셀렉터가 깨지면 테스트를 함께 갱신한다.

## 초기 프롬프트

```
청년안심주택 새 공고 알림 서비스 "청안"의 웹 UI를 디자인해 주세요.

## 서비스
서울시 청년안심주택 모집공고 사이트를 주기적으로 크롤링해 새 공고가 올라오면
구독자에게 웹 푸시·이메일로 알려주는 서비스입니다. 사용자는 알림을 받고 폰에서
링크를 열어 공고를 확인하는 경우가 가장 많습니다. 대상은 20~30대 청년이며, 주거
정보를 다루므로 신뢰감 있고 차분한 톤이어야 합니다. 화려한 마케팅 사이트가 아니라
"공고를 빠르고 정확하게 읽는 도구"입니다.

## 기술 제약 (반드시 지켜 주세요)
- Next.js App Router + React 19 + Tailwind CSS v4. Tailwind v4의 CSS-first 방식
  (`@import 'tailwindcss'` + `@theme`)으로 색·폰트 토큰을 globals.css에 정의해 주세요.
- shadcn/ui를 사용해 주세요(Tailwind v4 + `@theme inline` 방식). 컴포넌트는 실제로
  쓰이는 것만 추가하고(Button, Badge, Switch, Skeleton 정도), 필요 없는 컴포넌트를
  미리 깔지 마세요. 아이콘은 lucide-react, 화면당 2~3개 이내로 최소만.
- 표시 전용 컴포넌트는 서버 컴포넌트로 만들 수 있게 useState·onClick 없이 작성해
  주세요. 상호작용이 필요한 곳은 아래에 명시한 토글 버튼만입니다.
- 라이트 모드만 디자인합니다. 다크 모드는 만들지 마세요.
- 모바일 우선. 360px 폭에서 먼저 완성하고 1280px까지 자연스럽게 넓어지게 해 주세요.
  본문 최대 폭은 약 672px(max-w-2xl)입니다.
- 한국어 UI. 본문 폰트는 Pretendard Variable 하나만 씁니다(`--font-pretendard` CSS
  변수로 주입되고 폴백은 system-ui). 모노스페이스 폰트는 쓰지 않습니다.
- 접근성: 텍스트 대비 WCAG AA 이상, 키보드 포커스 링이 보여야 하고, 필터 칩의
  선택 상태는 색만이 아니라 형태로도 구분되어야 합니다.

## 화면 1 — 홈 (/)
서비스 한 줄 소개와 두 개의 진입점 [공고 목록 보기] [알림 받기]. 그 아래에
"최근 공고" 3건 미리보기(화면 2의 카드 재사용). 히어로 이미지 없이 텍스트와
여백으로 구성합니다.

## 화면 2 — 공고 목록 (/announcements)
- 제목 "공고 목록", 그 아래 결과 요약 한 줄 (예: "전체 42건", "조건에 맞는 공고 7건").
- 필터바: 두 줄의 칩 그룹.
  - 유형: [전체] [공공] [민간]
  - 모집: [전체] [최초모집] [추가모집]
  각 칩은 링크(<a>)이고, 선택된 칩은 aria-current="true"인 <span>입니다.
  Sprint 3에서 "지역구" 칩 그룹(서울 25개 자치구, 다중 선택)이 세 번째 줄로 추가될
  예정이니 그 확장을 감안한 레이아웃으로 해 주세요.
- 카드 리스트(<ul>/<li>, 카드 전체가 상세로 가는 링크):
  - 상단 배지 2개: 유형(공공/민간), 모집(최초모집/추가모집). 유형별 색을 구분해 주세요.
  - 제목 (2줄까지 표시 후 말줄임)
  - 위치 한 줄: "자치구 · 단지명" (둘 다 없을 수 있음)
  - 날짜 2개: "청약신청 2026-09-12", "게시 2026-09-05". 청약신청일이 더 중요합니다.
    청약신청일은 null일 수 있고 그때는 "미정"으로 표기합니다.
- 페이지네이션: [이전] [1] [2] [3] … [다음], 현재 페이지 강조.
- 빈 상태: "아직 등록된 공고가 없습니다." / 필터 결과 없음: "조건에 맞는 공고가 없습니다."
- 스켈레톤: 카드 5개 자리표시자.

## 화면 3 — 공고 상세 (/announcements/[boardId])
- 상단 "← 공고 목록" 뒤로가기 링크.
- 배지 2개 + 제목(h1).
- 핵심 정보 표(<dl>): 단지명 / 자치구 / 주택위치 / 세대수 / 공고게시일 / 청약신청일.
  값이 없는 항목은 행 자체를 숨깁니다. 청약신청일은 시각적으로 가장 강조합니다.
- 첨부파일 내려받기 링크 (있을 때만, 외부 링크 아이콘).
- "공고 본문" 섹션: 원본에서 추출한 평문 텍스트를 줄바꿈 보존(whitespace-pre-wrap)해서
  표시. 길이가 수천 자일 수 있습니다.
- 본문 끝에 안내 문장 + "원본 공고 보기 ↗" 외부 링크. 첨부 유무와 무관하게 항상 표시.
- 404 상태: "공고를 찾을 수 없습니다" + 목록으로 가는 링크.
- Sprint 4에 "지도"와 "청약 일정 타임라인" 섹션이 핵심 정보 표 아래에 추가될 예정이니
  섹션 구분 방식만 일관되게 잡아 주세요. 지금 그리지는 마세요.

## 화면 4 — 알림 구독 (/subscribe)
- 제목 "알림 구독".
- 비로그인 상태: 안내 문장 "알림을 구독하려면 먼저 로그인하세요." + 소셜 로그인
  버튼 2개 [Google로 계속하기] [카카오로 계속하기]. 카카오는 공식 노란색(#FEE500)을
  씁니다.
- 로그인 상태:
  - 계정 표시 한 줄(이메일) + [로그아웃] 텍스트 버튼.
  - "알림 채널" 섹션: 토글 카드 2개.
    - 웹 푸시: 제목·설명 한 줄·토글 스위치. 브라우저 권한이 거부된 상태의 안내 문구
      자리도 있어야 합니다.
    - 이메일: 제목·수신 주소·토글 스위치. 이 카드는 계정에 이메일이 없으면 렌더되지
      않습니다.
  - "알림 조건" 섹션 (Sprint 3 예정 — 자리만): "관심 지역구"와 "공고 유형" 두 항목을
    비활성 상태 또는 "준비 중" 표시로 배치해 주세요.
- 저장은 토글 즉시 반영되며 별도 저장 버튼은 없습니다. 토글 직후의 진행 중 상태와
  실패 시 인라인 오류 문구 스타일을 정의해 주세요.
```

## 이식 시 판단 기록

- **shadcn/ui 도입 확정** (ADR 016): v0 기본 출력이 shadcn/ui이고, Sprint 3 지역구
  다중 선택 필터에서 어차피 필요해진다. 지금 배제하면 이번에 만든 토글·배지·토큰을
  Sprint 3에서 한 번 더 고쳐야 하므로 Step a에서 함께 초기화한다. 컴포넌트는
  `src/components/ui/`에 복사되며, `cn()`은 기존 `src/lib/utils/cn.ts`를 가리킨다.
- **Pretendard Variable, `next/font/local` 셀프 호스팅**: 현재 `layout.tsx`는 Geist(라틴
  전용)를 로드하고 `body`는 Arial로 덮어써 한글 폰트가 없다. woff2 1개를 저장소에
  넣고 `next/font/local`로 로드해 레이아웃 시프트를 막는다(알림 링크를 폰에서 여는
  주 경로에서 체감). Geist·Geist Mono는 제거한다. 에셋 추가라 ADR은 쓰지 않고 학습
  문서에 남긴다.
- **상단 고정 헤더, 모바일도 동일**: 항목이 3개라 접을 이유가 없고, 주 사용 흐름
  (푸시 → 상세 → 닫기)에서 내비게이션 사용 빈도가 낮아 하단 탭바의 조작 이점이
  작다. 코드 한 벌·서버 컴포넌트 유지·Phase 4 웹뷰 앱의 네이티브 탭바와 비충돌.
- **다크 모드 제외**: 현재 `globals.css`의 `prefers-color-scheme: dark` 블록은 Step a에서
  제거한다. 라이트 전용으로 확정한 뒤 후속 Issue에서 다시 넣는다.
