# ADR 012: 목록 파서 row 격리 — 격리 vs 중단 경계

- **상태**: 제안됨
- **작성일**: 2026-08-31
- **관련 이슈**: #72 (배경: #42, #68)
- **관련 ADR**: 006 (카나리 불변식), 007 (상세 경로 row 격리)

## 맥락

크롤 동결이 두 달 새 두 번 발생했다(#42, #68). #68의 직접 원인은 신규 공고 1건(boardId 6624)이 `optn5`(모집유형) 미기재로 게시되자 `parseListJson`의 매핑 함수가 throw하며 **목록 전체 파싱이 중단**된 것이다. 파서가 `resultList.map(toListItem)` 구조라 한 항목의 실패가 전 항목을 무너뜨리고, cron이 500으로 동결되면 `last_board_id`가 전진하지 못해 매시간 같은 실패를 반복한다.

#69(optn5 제목 폴백)·#71(optn2 제목 폴백)은 **관측된 재발 경로만 닫는 전술적 방어**다. `nttSj` 누락, `regDate` 이상값, 미지의 새 분류 코드 등 나머지 항목 단위 실패는 여전히 전면 동결로 이어진다.

한편 원칙이 비대칭이다. 상세 크롤 경로는 이미 row 격리를 갖췄다 — 불변식 위반 detail은 `invalidBoardIds`로 격리하고 `last_board_id`는 latest까지 전진한다(ADR 007). 목록 파서에만 "한 항목 실패 = 전체 중단"이 남아 있다.

동시에, 격리를 도입하면 ADR 006과 긴장이 생긴다. ADR 006은 "사이트가 우리 밑에서 바뀌는 것"을 최악의 실패(살아있어 보이는 침묵)로 규정하고, 미지의 분류 코드 throw를 카나리가 500으로 잡는 신호로 썼다(#71 시점의 판단: "미지의 코드는 분류 체계 변경 신호이므로 throw해 카나리가 잡게 한다"). 항목 단위 실패를 조용히 건너뛰면 이 감지 능력을 잃을 수 있다. **"국지적 오입력은 격리하되, 구조 변경 감지는 잃지 않는" 경계**를 정해야 한다.

## 고려한 선택지

### 선택지 1: row 격리 + 기존 불변식으로 전면 붕괴 차단

`parseListJson` 출력을 "유효 항목 + 격리 항목(boardId·사유)"으로 분리 반환한다. 항목 단위 실패(미지의 분류 코드, 필드 누락, 이상 타임스탬프)는 해당 row만 격리하고, 격리 항목은 크롤 응답·로그에 표면화한다(상세 경로 `invalidBoardIds`와 동일한 지위). 리스트 불변식(ADR 006)은 무변경 — **전 항목이 격리되면 유효 배열이 비어 `LIST_EMPTY`가 cron 500으로 차단**한다.

- 장점: 국지적 오입력이 크롤을 동결시키지 못한다(#68 재발 경로 원천 차단). 상세 경로와 원칙이 대칭이 된다(ADR 007).
- 장점: 전면 붕괴(분류 체계 전면 개편, 키 소실)는 기존 카나리 경계가 그대로 잡는다 — 불변식 코드 무변경으로 경계가 성립.
- 단점: **부분적 구조 변경의 감지 강도가 내려간다.** 예: 새 분류 코드 '3'이 일부 신규 공고에만 도입되면 500 대신 응답 `isolated` + 로그로만 표면화된다. GHA 알림(`curl --fail`)은 status만 보므로 즉시 경보가 아니라 운영 관찰에 의존한다.

### 선택지 2: 격리 + 격리율 임계값 경보

선택지 1에 더해 "격리 항목이 N% 이상이면 500" 같은 임계값을 둬 부분 붕괴도 경보한다.

- 장점: 부분적 구조 변경도 자동 경보.
- 단점: ADR 006이 선택지 C(드리프트 추적)를 보류한 것과 같은 이유로 부적절 — **임계값을 정당하게 정할 운영 이력이 없다**. 페이지당 10건에서 1건 격리(10%)는 #68 같은 정상적 오입력인가 구조 변경의 전조인가? 지금 정하는 임계값은 검증 불가능한 추측이고, 불변식의 "이진(binary)" 원칙(정상이면 반드시 만족)을 깨뜨린다.

### 선택지 4: 격리 row도 view.do로 보강해 살리기

격리된 row도 boardId만 읽히면 크롤 후보에 넣는다. 저장되는 데이터는 전부 `parseDetailPage` 출력이고 목록 항목의 필드는 boardId 발견 용도로만 쓰이므로(ADR 003 옵션 B), 목록 매핑이 실패한 공고도 상세 페이지로는 온전히 수집될 수 있다.

- 장점: 국지적 오입력에서 알림 유실이 0이 된다. 목록 매핑 실패가 데이터 손실로 이어지지 않음.
- 단점: **미지의 분류 코드를 조용히 오분류한다.** `parseDetailPage`의 분류도 제목 휴리스틱('공공임대' 포함 여부)에 의존하므로, 사이트가 진짜 새 카테고리(예: 세 번째 주택 유형)를 코드 '3'으로 도입하면 그것을 public/private 중 하나로 **추측해 저장**한다. 잘못된 분류로 DB를 오염시키는 것은 알림 1건 유실보다 나쁘다 — 필터·알림 매칭이 그 분류에 의존하기 때문.
- 단점: "격리"의 의미가 흐려진다. 목록 데이터를 신뢰할 수 없다고 판정한 row를 같은 회차에 다시 신뢰하는 셈.

### 선택지 3: 현상 유지 + 관측된 실패 경로마다 폴백 추가

#69·#71처럼 실패가 관측될 때마다 해당 필드에 폴백을 추가한다.

- 단점: 대응이 항상 사후적이다 — 새 실패 경로마다 동결 1회(평균 감지~복구까지 크롤 정지)를 지불한다. 미지의 실패(예측 못 한 필드 이상)는 정의상 폴백을 미리 못 만든다.
- 단점: 상세 경로와의 비대칭이 영구화된다.

## 결정

선택지 1 — `parseListJson`을 row 격리로 전환하고, 전면 붕괴 차단은 기존 리스트 불변식(`LIST_EMPTY`)에 위임한다.

격리 vs 중단의 경계는 다음과 같이 정한다:

| 실패                                                                                                    | 판정                       | 동작                                          |
| ------------------------------------------------------------------------------------------------------- | -------------------------- | --------------------------------------------- |
| JSON 자체가 invalid (파싱 불가)                                                                         | 응답 전체 이상 = 구조 변경 | 기존대로 throw → cron 500                     |
| 항목 단위 실패 (미지의 optn2/optn5 코드, `nttSj` 누락·비문자열, `regDate` 비정상, `boardId` 비양의정수) | 국지적 오입력              | 해당 row만 격리, 사유와 함께 응답·로그 표면화 |
| 전 항목 격리 (유효 0건)                                                                                 | 전면 붕괴 = 구조 변경      | `LIST_EMPTY` 불변식 → cron 500 (무변경)       |

`latestBoardId`는 **격리 row의 boardId(파싱 가능한 경우)도 포함해 전진**한다. ADR 007의 기존 정책("`last_board_id`는 위반 row가 있어도 latest까지 전진")과 정합하며, 포함하지 않으면 격리 항목이 매 회차 재관측되어 영구 노이즈가 된다. 격리 항목의 알림 유실은 상세 경로 `invalidBoardIds`와 같은 수준에서 수용한다.

## 근거

- **동결 비용 > 감지 지연 비용.** 동결은 서비스의 존재 이유(신규 공고 알림)를 전면 정지시키고, #42·#68 모두 감지~복구까지 수 시간~수 일의 크롤 공백을 만들었다. 반면 부분적 구조 변경의 감지 지연은 격리 항목이 응답에 계속 표면화되므로 침묵이 아니다 — ADR 006이 경계한 "살아있어 보이는 침묵"과 다르다.
- **경계가 이진 원칙을 지킨다.** "유효 0건 = 중단"은 카운트 휴리스틱이 아니라 구조 불변식이다(정상 응답이면 반드시 유효 항목이 존재). 임계값(선택지 2)처럼 운영 이력이 필요한 추측이 없다.
- **원칙의 대칭 복원.** 상세 경로(ADR 007)와 목록 경로가 같은 격리 원칙을 갖게 되어, "단일 불량 row는 회차를 막지 않는다"가 파이프라인 전체의 일관된 계약이 된다.
- 선택지 4(격리 row를 view.do로 살리기)를 **의도적으로 배제**한다. 유실 0을 얻는 대가로 "모르는 분류를 추측해 저장"하게 되는데, 알림 매칭·필터가 그 분류에 의존하므로 오분류 저장이 유실보다 비싸다. 격리는 "모른다고 말하고 멈추는" 선택이다.
- #71 시점의 "미지의 코드는 throw해 카나리가 잡게 한다"는 판단을 **부분 폐기**한다: 그 판단은 감지를 위해 가용성을 지불했는데, #68이 보여주듯 그 지불이 과도하다. 전면 개편은 여전히 잡히고(LIST_EMPTY), 부분 도입은 격리 표면화로 관찰한다.

## 결과

- `parseListJson` 출력 계약 변경: `AnnouncementListItem[]` → `{ items, isolated: { boardId: number | null, reason: string }[] }`. 항목 shape 방어 검증(boardId·nttSj·regDate)이 추가된다.
- 소비자 정합: `announcementService`(신규 후보·페이지네이션은 유효 items 기준, 결과에 격리 항목 추가), `canary`(유효 items에 불변식 적용 — 동작 동일), `/api/cron/crawl`(응답·`console.warn` 표면화).
- #69·#71의 제목 폴백은 유지한다 — 폴백은 "복원 가능한 미기재"를 데이터로 살리고, 격리는 "복원 불가능한 이상"을 배제한다. 폴백이 있는 한 미기재는 격리에 도달하지 않는다.
- 부분적 구조 변경(새 분류 코드의 점진 도입)의 일차 관측 창구는 크롤 응답의 격리 필드와 로그다. 자동 경보로 승격할지는 운영 이력이 쌓인 뒤 재평가한다(ADR 006 선택지 C와 같은 보류).
