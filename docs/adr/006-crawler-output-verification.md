# ADR 006: 크롤러 출력 검증 전략 — 불변식 + 라이브 카나리

- **상태**: 수락됨
- **작성일**: 2026-06-12

## 맥락

청안은 알림 서비스이고, 최악의 실패는 다운이 아니라 *살아있어 보이는 침묵*이다. 크롤링 대상 사이트(soco.seoul.go.kr)가 응답 형태를 바꾸면 파서가 throw 없이 빈 값을 통과시키는 silent-failure 경로가 존재한다:

- **S1** (`announcementService.ts:142`): JSON `resultList`가 비거나 키가 바뀌면 `items.length === 0` → `latestBoardId: lastBoardId` 반환 → `newCount`가 영원히 0인데 응답은 200 OK. (이 API는 "신규분"이 아니라 게시판 1페이지 = 항상 최신 N건을 반환하므로, **빈 resultList ≠ 신규 0건**이다. 정상적인 "신규 0건"은 resultList가 꽉 찬 채 max boardId가 `lastBoardId`와 같아 catch-up 범위만 비는 `:150` 이후 경로다. 6500건 넘게 누적된 게시판에서 page 1이 0건이면 게시판 초기화·응답 형태 변경·키 소실 중 하나이며, `parseListJson`은 `resultList ?? []`로 키 소실도 throw 없이 통과시킨다.)
- **S2** (`parseDetailPage.ts`): `p.subject`·`ul.view_data`·`div.board_cont` 등 셀렉터가 전멸하면 `title=''`, 필드 null인 채 throw 없이 반환 → 빈 껍데기 레코드가 DB에 저장.
- **S3** (`isViewErrorPage`): 633B 에러 페이지 포맷 변경 시 skip 오분류.

기존 `__fixtures__` 계약 테스트는 *우리 코드의 회귀*만 잡는다. 박제된 과거 응답이므로 *사이트가 우리 밑에서 바뀌는 것*은 원리상 감지할 수 없다. 그런데 silent failure는 바로 운영 중에 일어난다. #36(부트스트랩 109분 루프)도 같은 계열의 "조용한 운영 실패"였다.

## 고려한 선택지

### 선택지 A: CI 픽스처 계약 테스트 강화만

박제 픽스처에 대한 단위 테스트를 더 촘촘히.

- 장점: 추가 운영 인프라 0. 기존 테스트 흐름 그대로.
- 단점: 사이트 변경을 **원리상 못 잡는다**. 가장 위험한 S1/S2는 운영 중 발생하는데 CI는 박제 응답만 본다.

### 선택지 B: 불변식 함수 + 라이브 카나리

파서 출력의 불변식을 순수 함수로 추출(`parserInvariants`)하고, 이를 매 크롤 회차에 _라이브 사이트_ 응답에 적용. 위반 시 cron 500 → GHA `curl --fail` 알림.

- 장점: 사이트 드리프트를 운영 중 감지. 불변식은 이진(binary)이라 위반/정상이 명확하고 변형 픽스처로 즉시 증명 가능. 같은 함수를 CI 픽스처 테스트도 재사용(A를 포섭).
- 단점: 크롤 핸들러에 검증 단계 추가(소폭 결합). 안정 boardId 1건을 카나리로 선정·유지해야 함.

### 선택지 C: 드리프트 추적 (확률적 임계값 경보)

`skippedBoardIds` 비율, 빈필드 레코드 비율 등을 회차마다 DB에 기록하고 임계값 초과 시 경보.

- 장점: 불변식으로 안 잡히는 점진적 열화(부분 셀렉터 변경 등)까지 포착.
- 단점: 임계값을 정당하게 정하려면 **운영 이력이 필요**한데, 서비스가 막 부트스트랩을 끝내 그 이력이 없다. 지금 임계값은 추측이 되고 오경보 검증이 불가능. 마이그레이션·상태 관리 추가.

## 결정

선택지 B를 채택한다 — `parserInvariants` 순수 함수로 리스트/디테일 불변식을 정의하고, 매 크롤 회차에 라이브 응답에 적용해 위반 시 크롤을 실패(500)시킨다. 같은 함수를 CI 픽스처 테스트에서도 재사용한다. 선택지 C(드리프트 추적)는 **의도적으로 이번 범위에서 제외**하고, 운영 이력이 쌓인 후 별도 작업으로 분리한다.

## 근거

- 픽스처(A)는 사이트 변경을 원리상 못 잡으므로 가장 위험한 S1/S2를 방어하지 못한다. 라이브 카나리만이 그 공백을 메운다.
- 불변식은 이진이라 "진짜 조용한 시기 vs 파서가 깨짐"을 명확히 가른다 — 연속 0건만으로 경보하면 부트스트랩·한산한 시기와 구분 불가하므로, 카운트가 아니라 *구조 불변식*을 검증 대상으로 삼는다.
- C를 보류하는 것은 정직성의 문제다. 운영 이력 없이 정한 임계값은 검증 불가능한 추측이다. 무엇을·왜 미뤘는지 명시해 둔다(YAGNI).
- 위반을 cron 500으로 표면화하면 이미 있는 GHA `curl --fail` 경보 경로(ADR 004)를 그대로 재사용한다 — 새 알림 채널 불필요.

## 결과

- `src/lib/crawler/parserInvariants.ts` 신설 — 위반을 구조화해 반환(throw ❌):
  - **리스트 불변식**: 결과 배열 비어있지 않음, 각 item `boardId` 양의 정수, `title` trim 후 비어있지 않음.
  - **디테일 불변식**: (에러 페이지가 아닌데) `title`과 `rawContent`가 동시에 비면 위반(셀렉터 전멸), `postDate` 날짜 형태.
- 변형 픽스처(셀렉터 깨진 HTML / `resultList` 비운 JSON)로 위반 검출을 검증하는 단위 테스트.
- 크롤 파이프라인에 검증 통합: 매 회차 리스트 불변식 + 안정 boardId 1건 detail 불변식 검증, 위반 시 500. 안정 boardId 선정은 통합 단계에서 결정.
- 드리프트 추적은 후속 이슈로 분리(이 ADR이 그 경계를 기록).
